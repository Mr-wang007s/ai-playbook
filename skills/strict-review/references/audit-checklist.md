# 轻量模型编码高频翻车点核查表（Audit Checklist）

在审查由快模型/弱模型生成的代码时，优先定向排查以下高频缺陷模式：

## 1. 偷工减料与幻觉类（Hallucination & Shortcuts）
- **类型强转糊弄**：遇到类型报错不修上游接口，直接套 `as any`、`as unknown as T` 或加 `// @ts-expect-error`。
- **静默吞错**：`try { ... } catch { return null; }` 把真实运行时异常全部吞掉，且不打日志、不回滚中间状态。
- **半截实现**：只改了写入路径没改读取路径，或只改了内存态没同步持久化/事件通知。
- **编造 API**：调用了看似合理但项目工具库/标准库中根本不存在的方法或配置项。

## 2. 状态、缓存与并发类（State, Cache & Concurrency）
- **缓存键漏维度**：新增了影响输出结果的过滤条件或元数据字段，但旧缓存键生成函数未将其纳入签名，导致命中陈旧缓存。
- **真假值陷阱（Falsy Trap）**：用 `if (val)` 或 `val || defaultVal` 处理合法的 `0`、`false`、`""`，应改用 `!= null` 或 `??`。
- **异步时序倒置（Stale Closure / Race Condition）**：连续触发异步请求时，先发后至的旧响应覆盖了新状态，缺少请求序号校验或 `AbortController`。
- **原地变异污染**：在计算派生数据时直接 `.sort()`、`.splice()` 或修改入参对象属性，污染了上游 Store 或缓存快照。

## 3. 虚假测试类（Ineffective / Tautological Tests）
- **测 Mock 不测实现**：把被测模块内部关键函数甚至被测方法自己 Mock 成固定返回值，然后断言返回值等于该固定值。
- **只测正例漏反例**：比如修的是“同版本号下删除子项要穿透缓存”，单测却在构造测试数据时顺手改了版本号，根本没测到“同版本号穿透”的真实修复点。
- **弱断言**：只检查 `expect(fn).toHaveBeenCalled()`，未检查传入参数与最终落盘状态是否剔除了脏数据。
