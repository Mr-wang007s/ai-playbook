# 实战经验萃取与分层沉淀（Experience Distillation）

当用户显式调用本技能时，说明刚刚经历了一次值得复用的踩坑纠偏或摸索出了高效的协作模式。你的任务是**把散落在聊天记录里的临时纠偏，提炼为高信噪比、结构化的长效工程资产**。

---

## 第一步：回溯与提炼（去水留干）

回顾当前会话（或聚焦用户附带指出的具体经验），回答三个问题：
1. **踩了什么坑 / 解决了什么低效环节？**（AI 最初为什么做错了？缺了什么上下文或边界约束？）
2. **真正起效的关键约束或步骤是什么？**
3. **剔除一次性业务细节后，可复用的通用规则是什么？**

---

## 第二步：四层归属路由（严防全局上下文膨胀）

按以下标准决定经验应该沉淀到哪一层：

| 经验性质 | 目标层级与落盘位置 | 预算与准入铁律 |
| :--- | :--- | :--- |
| **仅限当前业务项目**：目录职责、定向构建/单测命令、特定模块爆炸半径、项目专属代码规范 | **L3 项目地图层**：当前业务仓库根目录或对应子包下的 `AGENTS.md`（若项目尚无 `CLAUDE.md` 且使用 Claude Code，可建 `CLAUDE.md` 写入一行 `@AGENTS.md` 单源共用） | 按模块分节，只写代码里看不出来的隐性契约与精确命令 |
| **跨项目通用的专项工作流 / SOP**：多步骤流程、检查单、特定角色视角（如 `plan-runbook`、`strict-review`） | **L2 全局插件技能层**：个人 `ai-playbook` 源码仓库下的 `skills/<skill-name>/SKILL.md`（更新现有技能或新建带 `disable-model-invocation: true` 的技能） | 平时 0 Token 开销；单文件保持在 300 行以内，长参考拆入 `references/` |
| **跨所有项目 100% 永远适用的铁律**：每次对话都必须遵守的极简行为红线 | **L1 全局底线层**：`ai-playbook/rules/global-coding-rules.md` 或用户全局规则配置 | **极度克制**：单条不超过 2 行，全局总长度严控在 **50 行以内**；能放 L2/L3 的绝不塞进 L1 |

> **注意**：若目标为 **L2 全局插件技能层**，请写入本机克隆的 `ai-playbook` Git 源码仓库（例如 `~/codespaces/ai-playbook`；若不确定本地克隆路径，先向用户确认，**切勿**直接修改 `~/.claude/plugins/cache/` 下的只读缓存副本）。

---

## 第三步：先给精炼草稿确认，再落盘推送

1. 向用户展示：
   - **建议归属层级与目标文件路径**（说明为什么放这一层）；
   - **拟新增或修改的精炼内容预览**（做到字字有用，删除一切正确的废话）。
2. 用户确认后执行写入：
   - 若写入的是 `ai-playbook` 插件源码仓库，无需手动修改 `.claude-plugin/plugin.json` 的 `version`（仓库合并/推送到 `main` 后由 GitHub Actions 自动递增补丁版本号）；
   - 提醒用户在 `ai-playbook` 仓库执行 `git add -A && git commit && git push`，其他设备开启 Marketplace 自动更新或执行 `npx skills update -g` 即可同步最新版。
