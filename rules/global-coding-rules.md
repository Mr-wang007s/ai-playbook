# Global AI Coding Rules (L1 Baseline)

> 保持极简（全文严格控制在 50 行以内）。这里只放跨所有项目、每一轮对话都必须遵守的底线纪律；具体工作流请放入 `skills/`，项目特有规范请放入各仓库的 `AGENTS.md`。

## 沟通与表达
- 默认使用中文回复；代码标识符、文件路径、命令与技术术语保持原样，并用反引号包裹。
- 结论先行，直击根因，省略客套寒暄与显而易见的铺垫解释。

## 编码与改动边界
- **最小爆炸半径**：只修改与当前任务直接相关的代码；未经明确要求，禁止顺手重构旁路逻辑、重命名公共接口、调整无关文件格式或升级依赖版本。
- **先读后改**：修改任何文件前必须先读取真实上下文，核实上下游类型与调用方，严禁臆造项目中不存在的 API 或用 `as any` 掩盖类型错误。
- **尊重现有风格**：严格对齐目标文件所在目录既有的命名、缩进、引号、错误处理与单测构造方式。

## 测试与验证时机
- 每次修改完代码或测试文件后，**不要**在中间步骤自动运行耗时的全量单测、集成测试或全仓 Lint / Typecheck。
- 仅在以下时机执行测试与校验，且优先运行**精确到改动文件/子包的定向命令**：
  1. 用户明确指令要求运行测试或检查时；
  2. 准备执行 `git commit` 或创建 PR/MR 之前。
